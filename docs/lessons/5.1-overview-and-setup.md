# 5.1 ハンズオンの全体像と演習環境の準備

## 目的

GitHubアカウントと演習用リポジトリを準備し、GitHub Actions、merge方式、main branch用Rulesetの基本設定を行う。あわせて、使い捨てUT環境面、品質ゲート、証跡がハンズオン全体でどのようにつながるかを理解する。

## 開始状態

- GitHubアカウントを持っていなくても開始できる。
- GitHubアカウントを既に持っている場合は、アカウント作成を省略してサインイン確認から始められる。
- 演習用リポジトリはまだ作成されていない。
- 公開テンプレートリポジトリから、受講者本人が所有する独立した演習用リポジトリを作成する前の状態である。

## 終了状態

- GitHubアカウントが準備され、GitHubへサインインできる。
- 受講者本人の個人GitHubアカウントをOwnerとする演習用リポジトリが作成されている。
- GitHub Actionsを利用でき、workflow permissionsを確認できている。
- Squash mergeとMerge commitが有効、Rebase mergeが無効になっている。
- main branch用Rulesetの基本設定が保存されている。
- `pr-ci-gate`はまだRequired status checkへ登録していない。
- 5.2で最小PR CIを一度成功させた後、`pr-ci-gate`を登録してRulesetを`Active`にすることを理解している。

## 操作手順

### 1. GitHubアカウントを準備する

[GitHubアカウントとテンプレートリポジトリの準備](../setup/github-account-and-template.md)を開き、GitHubアカウントを持っていない場合は作成とメールアドレス確認を行う。既に持っている場合は、受講に使う個人アカウントでサインインしていることだけを確認する。

### 2. 公開テンプレートから演習用リポジトリを作成する

同じ[準備手順](../setup/github-account-and-template.md)に従い、公開テンプレート`RanamicusTechnology/11-env-hands-on`から演習用リポジトリを作成する。forkではなく、受講者本人の個人アカウントがOwnerの新しいリポジトリとして作成する。

### 3. Public利用時の注意を確認する

GitHub FreeではPublicリポジトリを使用する。GitHub ProではPublicまたはPrivateを選択できる。Publicを選ぶ前に、secret、token、個人情報、顧客情報、業務情報、実在システムの設定値を登録せず、教材用ダミー情報だけを使うことを[準備手順](../setup/github-account-and-template.md)で確認する。

### 4. GitHub Actionsとworkflow permissionsを確認する

[リポジトリ設定手順](../setup/repository-settings.md)のPhase Aに従い、`Settings`からGitHub Actionsが利用可能であることを確認する。`Workflow permissions`はreadを基本とし、必要以上のwrite権限を与えない。

### 5. merge方式を設定する

[リポジトリ設定手順](../setup/repository-settings.md)に従い、次の設定にする。

- Squash merge: 有効
- Merge commit: 有効
- Rebase merge: 無効

### 6. main branch用Rulesetの基本設定を保存する

[リポジトリ設定手順](../setup/repository-settings.md)のPhase Aに従い、main branchを対象とするRulesetを作成する。Bypass listは空にし、管理者用bypassを設定せず、main branchの削除とforce pushを許可しない。5.1ではRequired status checkを設定せず、Rulesetは`Disabled`で保存する。

### 7. 5.2へ持ち越す設定を確認する

新しいリポジトリでは、まだ`pr-ci-gate`の成功履歴がない。5.2でIssue、branch、Draft Pull Requestを作成し、最小PR CIの`pr-ci-gate`が成功した後に、同じRulesetを編集する。その時点で`pr-ci-gate`をRequired status checkへ追加し、strict設定とRulesetの`Active`化を行う。

## ハンズオン全体で扱う関係

CIと使い捨て環境は、受講者のローカルPCではなくGitHub-hosted runner上で動作する。品質ゲートはPull Request作成を禁止するものではなく、不備のある変更がmainへmergeされることを防ぐ。

変更Issueは、変更要求、受入条件、変更対象、`target_version`、`required_final_stage`の正本である。Test run ID、Environment face ID、Build Artifact IDなどの実行時情報はGitHubまたはworkflowが生成するため、受講者がIssue本文へ固定値として入力しない。

Build Artifactはchecksumで同一性を確認する。テスト結果と証跡はjobごとのActions Artifactとして管理し、Job SummaryをTest run ID、Issue、Pull Request、workflow run、job結果、Artifact名の索引として使用する。

## 5.1完了チェック

- [ ] GitHubへサインインできる。
- [ ] 演習用リポジトリのOwnerが自分の個人GitHubアカウントである。
- [ ] GitHub FreeではPublic、GitHub Proでは選択したVisibilityになっている。
- [ ] テンプレート元とは独立したリポジトリであり、fork表示ではない。
- [ ] GitHub Actionsを利用できる。
- [ ] Workflow permissionsがreadを基本とする設定になっている。
- [ ] Squash mergeとMerge commitが有効、Rebase mergeが無効になっている。
- [ ] main branch用Rulesetの対象、Bypass list、削除制限、force push制限を確認した。
- [ ] RulesetはRequired status checkなし、`Disabled`で保存されている。
- [ ] `pr-ci-gate`は5.2の初回成功後に追加することを理解している。
