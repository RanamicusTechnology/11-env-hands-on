# 5.3 静的解析・単体テスト・ビルド・アーティファクト管理

## 目的

PR CIにGoアプリケーションの静的解析、Go単体テスト、build/package、証跡Artifact、一時Build Artifact、`pr-ci-gate`の集約判定を追加し、変更要求から成果物・証跡までを追跡できる状態にする。

このレクチャーでは対象をGoアプリケーションに限定する。UT環境面は5.4、正式インフラ/APIテストは5.5で扱う。Terraform / Ansible静的解析、Promotion Candidate Record、Release Candidate登録はセクション5の受講者向けPR CIでは扱わない。

## 開始状態

5.2の段階資源がcommit済みで、Draft Pull Requestと最小PR CIが作成されている状態。`.github/workflows/pr-ci.yml`には`governance-check`と`pr-ci-gate`があり、`evidence-governance_<test-run-id>`を保存できる。

## 終了状態

PR CIに次のjobが追加されている。

- `static-analysis`
- `unit-test`
- `build-package`

`pr-ci-gate`は、`governance-check`、`static-analysis`、`unit-test`、`build-package`のjob result、論理結果、必須outputs、証跡Artifact upload結果、一時Build Artifact upload結果を集約する。

このレクチャーで扱うBuild Artifactは、PR CI内で一時利用する`build-go-app_<test-run-id>`である。Promotion / Releaseで使う正式Build Artifact名ではない。

## 受講者が操作・確認する内容

- cleanなworking treeで`bash scripts/exercises/apply-learning-stage.sh --check 5.3`を実行する
- `bash scripts/exercises/apply-learning-stage.sh 5.3`で5.3 patchを適用し、`git diff --check`と`git diff`で差分を確認する
- 5.3のCI結果を確認した後、5.4を適用する前に5.3の変更をcommitする
- Go Web APIの小さな処理またはテストを追記する
- 変更Issueの`target_version`とルートの`VERSION`を一致させる
- この段階演習では`target_version: 0.0.0`とルートの`VERSION`を維持する
- PR CIで`gofmt -l .`と`go vet ./...`が実行されることを確認する
- gotestsumによりGo単体テストのJUnit XMLが生成されることを確認する
- `target_version`、ルート`VERSION`、Build Artifact versionの`X.Y.Z`が一致することを確認する
- GoアプリのLinux amd64バイナリ、checksum、manifestがBuild Artifactへ保存されることを確認する
- `evidence-static-analysis_<test-run-id>`、`evidence-unit-test_<test-run-id>`、`evidence-build-package_<test-run-id>`の内容を確認する
- `pr-ci-gate`のJob SummaryでTest run ID、各job結果、証跡Artifact名、Build Artifact名、checksumを確認する
- Go単体テストはUT環境上のプロセス起動、port listen、Nginx経由疎通を検証しないことを確認する

## 学習上重要なポイント

Goアプリ単体テストは、入力と期待値、エラー処理、`/health`レスポンス生成ロジック、version値組み立てなど、Goコードのロジックを検証する。Build Artifactとして生成したGoバイナリがUT環境上で期待パスに配置され、実行権限を持ち、process/port/Nginx経由で動作するかは5.4のUT環境上の起動・疎通確認と5.5のインフラ/APIテストで確認する。

Build Artifactと証跡Artifactは分離する。Build Artifactにはバイナリ、checksum、manifestを含める。静的解析、単体テスト、build/packageのログやJUnit XMLは証跡Artifactとしてjobごとに保存し、証跡Artifact独自のchecksumを品質ゲート条件にはしない。

`pr-ci-gate`は再build、再テスト、証跡再生成を行わない。先行jobの結果、job outputs、Artifact upload結果、Build Artifact checksumの有無を集約し、品質ゲートとしてmainへのmerge可否を制御する。

このレクチャーでは`candidate_id`、Promotion Candidate Record、Promotion Record、Release Candidate登録を扱わない。`build-go-app_<test-run-id>`はPR CI内の一時名であり、Promotion / Releaseで使う正式命名ではない。
